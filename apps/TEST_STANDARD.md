# Claude AppStore 测试标准

每个 app 发布前必须按这个标准测完。**发布门槛：P0、P1 为零。** 用户打开就能碰到的问题都算 P0。

## 1. 缺陷分级

| 级别 | 定义 | 例子 | 处理 |
|---|---|---|---|
| P0 | 核心功能用不了，或者丢数据 | 按钮点不动；打字没反应；中文输入丢字；保存后内容丢失；打开就报错白屏 | 必须修，修完重测 |
| P1 | 主要功能出错，有绕过办法 | 导出文件打不开；撤销失效；某个菜单项报错 | 必须修 |
| P2 | 次要功能出错或体验差 | 窄窗口下按钮挤压；提示文字不准 | 记录，尽量修 |
| P3 | 外观小毛病 | 对齐差 1 像素；个别词没翻译 | 记录 |

## 2. 测试分层

### 2.1 冒烟测试（每个 app 都跑，自动）
脚本：`scratchpad/qa-std/smoke_all.mjs`
- 中文、英文环境各打开一次，0 个页面错误（pageerror），控制台没有本应用的报错。
- **每个可见控件都点得到**：按钮、链接、输入框、下拉框、可编辑区，在中心点做命中检测，最上层必须是它自己（没有被遮挡层、拖动层、透明层盖住）。
- **每个可见按钮都点一下**（跳过会下载文件、会删除数据的），点完没有页面错误；有弹出菜单或对话框的，按 Esc 能关掉。
- 模拟“已安装”窗口：读出 app 设置的窗口选项，没有任何控件落在 `dragHeight` 拖动层里，也没有落在 `app-region:drag` 区域里却没标 `no-drag`。

### 2.2 关键用户路径（每个 app 3 到 5 条，用真实鼠标键盘）
每条路径从新用户空数据开始，用 `page.mouse` / `page.keyboard` 真实点击和打字，做完检查结果：
- 新建或打开 → 编辑（英文 + 中文输入法）→ 撤销/重做 → 保存或导出 → 重新打开还在。
- 用 Claude 的路径：用桩（stub）返回真实样子的回答，检查界面正确显示、可以接受/拒绝/撤销。
- **按钮和快捷键都要测**：每个动作既按快捷键，也要用鼠标点工具栏、菜单里对应的按钮，并检查确实生效（2026-11-26 幻灯片的撤销按钮没接线，只有 ⌘Z 能用，之前的测试只按了快捷键所以没发现）。
- 导出的文件要用对应的库重新读回来检查内容（docx/xlsx/pptx 解压、pdf 用 pdf-lib 读、视频检查时长、图片检查尺寸）。

### 2.3 环境矩阵
| 维度 | 取值 |
|---|---|
| 语言 | en-US、zh-CN（这台 Mac 默认中文，必须显式设 locale） |
| 主题 | 浅色、深色 |
| 宽度 | 1280、900、600、400 |
| 存储 | 正常、localStorage/indexedDB 抛错 |
| 运行方式 | 浏览器里、模拟已安装窗口 |

### 2.4 人眼走查（内置浏览器，真实鼠标）
在内置浏览器里打开测试页，用鼠标把关键路径点一遍，截图存档，检查：界面没有错位、空状态说得清楚、错误提示说人话、加载中有反馈。

### 2.5 装好后的真实窗口
装好的 artifact app 在电脑操作里只给只读权限，我们点不了。发布后请用户在装好的窗口里按“首次打开清单”（第 4 节）点一遍。

### 2.6 深测（每轮大版本前跑，比 2.2 更细）
2.2 只测关键路径，深测要把**每一个**功能都过一遍，按下面 10 项逐项打勾，每项写明测了哪些控件、结果如何。
1. **控件清单 100% 覆盖**：从源码列出所有按钮、菜单项、右键菜单项、设置开关、键盘快捷键（搜 keydown 处理），做成清单；每一项都用鼠标点一次（有快捷键的再按一次），检查确实生效。清单里每一行都要有结果。
2. **撤销/重做**：每种编辑操作各做一次，连续撤销到底再重做到头，内容一致；撤销后刷新页面，状态正确。
3. **持久化**：每种操作做完都刷新页面，内容还在；同时开两个标签页改同一份数据，不会互相覆盖坏、不会白屏。
4. **边界数据**：空内容、1 个字、1 万字长文、表情符号、中日韩混排、从右到左文字、`<script>alert(1)</script>`、`"'&<>`（必须原样显示，不能执行）、1000 条数据、超大文件、损坏文件、错误类型文件。
5. **Claude 失败**：桩分别返回 `not_granted`、`rate_limited`、网络错误、`truncated:true`、`sample.json` 给错格式、10 秒才回答（中途取消）、等待中再点一次发送、`claude.use` 返回 null。每种都要有说人话的提示，界面不卡死，能重试。
6. **快速操作**：按钮连点两下、快捷键连按、操作中途改窗口大小、对话框里按 Esc / Enter / Tab，焦点顺序合理，不会重复提交。
7. **输入法**：每一个文本输入框都用输入法组字打中文；组字过程中按回车只确认候选词，不能提交、不能换行、不能触发快捷键。
8. **导入导出往返**：每种格式都导出再导回，内容一致；中文文件名能正常保存。
9. **语言和主题**：中文模式下每个对话框、菜单、提示、报错都没有残留英文（用户内容除外）；英文模式没有中文；深色模式下每个对话框都看得清。
10. **时间和数字**：日期、时区、月末、闰年、夏令时、货币小数、负数、超大数字，显示和计算都对（记账、健身、番茄钟、世界时钟、求职重点测）。

**判级要严**：主要功能有一次出错、数据有一次不对、某个按钮没效果，都按 P1 以上算；拿不准算高一级。深测发现的 P0/P1 当场修好并回归，修完不能让冒烟测试和死按钮检测变红。

## 3. 发布流程
1. 冒烟测试全绿。
2. 关键用户路径全过。
3. 环境矩阵无 P0/P1。
4. 内置浏览器人眼走查完成，截图存档。
5. 写测试报告：测了什么、怎么测的、发现和修复了哪些问题、哪些测不了。
6. 发布。

## 4. 首次打开清单（给用户在装好的窗口里点）
1. 顶部工具栏每个按钮都点一下。
2. 新建一个内容，打几个中文和英文。
3. 撤销一次。
4. 导出一次。
5. 关掉再打开，内容还在。
